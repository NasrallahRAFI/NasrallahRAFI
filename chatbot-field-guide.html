The big picture

Two parts. One conversation.

Your website is where people type. Your backend is the private go-between that talks to the AI.

01 · VISITORAsks a question in the chat widget.
02 · PORTFOLIOStatic site on GitHub Pages sends it over HTTPS.
03 · BACKENDChecks the request, finds relevant portfolio facts, calls the AI.
04 · GEMINIGoogle’s model drafts a structured answer.
05 · BACK AGAINBackend checks the answer, then the site displays it.

Public site: GitHub Pages · Private API: Azure VM behind Cloudflare and Caddy · AI provider: Google Gemini.

Say it simply

“The site and the chatbot server are separate. The server checks each question and passes it to Gemini without exposing my API key in the browser.”

The technology choices

A small, practical stack.

Think of the stack as the set of tools assigned to each job.

Language
JavaScript on Node.js — the server’s programming language and runtime.
Web framework
Express 5 — receives web requests and routes them to the right code.
AI provider
Google Gemini through Google’s official JavaScript SDK.
Database
SQLite — a small local database for daily usage and budget counts.
Front door
Cloudflare → Caddy — Cloudflare filters public traffic; Caddy handles secure HTTPS and passes requests to the app.
Runtime
Ubuntu · Azure VM · systemd — the rented server runs and supervises the backend process.
Say it simply

“The backend is JavaScript on Node and Express, it uses Gemini for AI, and SQLite keeps track of usage limits.”

How an answer gets made

A guided answer,
not a free-for-all.

The bot is designed to talk about your portfolio. It looks up related project notes, asks Gemini to draft, then checks the result.

Grounded in your work

  • Project information lives in editable Markdown files.
  • A small index helps match a question to relevant topics.
  • Only a few relevant project notes are sent along with the question.
  • Answer links and actions are checked against an approved list.

Kept within bounds

  • The system prompt defines the bot’s role and limits.
  • Only the most recent eight messages go to Gemini.
  • Gemini is asked for a predictable, structured response.
  • Low-confidence project questions can get a clarification request.
Say it simply

“I gave it organized facts about my projects, so it can find relevant details instead of relying only on a generic AI’s memory.”

Security · protecting the secret

The browser never
gets the key.

The Gemini key stays in a private server-side environment file. The server checks its configuration when it starts.

Secrets stay server-side

The AI credential is stored in backend environment configuration. It is not sent to the visitor’s browser as part of the design.

Browser requests are scoped

CORS allows configured browser origins; Helmet adds security headers and JSON requests have a 10 KB cap. CORS is a browser rule, not an identity check.

Origin check›Request limits›Input checks›Abuse checks›AI budget
Say it simply

“The AI secret lives on the server, not inside the website code visitors can inspect.”

Say it simply

What the project folders mean

A place for each job.

You don’t need to memorize every filename. Remember the shape.

The front door

routes/

Defines API paths such as /api/v1/chat and which checks run first.

The reception desk

middleware/

Reusable request checks: rate limits, validation, abuse controls, and request IDs.

The coordinator

controllers/

Connects the web request to the chatbot work and returns the response.

The workbench

services/

Builds context, calls Gemini, and checks the resulting answer.

The reference shelf

data/

Portfolio facts and indexes the chatbot can search for relevant details.

The ledger

database/

SQLite setup and the records used to keep AI usage within budget.

Say it simply

“The backend is split into request checks, chat handling, AI and knowledge services, and a small usage database.”
